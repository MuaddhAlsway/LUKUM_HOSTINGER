EVENT VIDEO DISPLAY - COMPLETE FIX
════════════════════════════════════════════════════════════════════════════════

PROBLEM:
Video URLs saved in exhibitions admin panel were NOT showing on event detail page

ROOT CAUSE:
1. API get_event_details.php only searched events table (not exhibitions table)
2. When clicking past exhibition from spaces.php → no exhibition found → no video

SOLUTION IMPLEMENTED:

File: api/get_event_details.php
──────────────────────────────────────────────────────────────────────────────

1. SLUG LOOKUP FIX (Line ~110):
   - Now searches exhibitions table if not found in events table
   - Compares title_en with normalized slug
   
2. MAIN QUERY FIX (Line ~155):
   - If event not found in events table
   - Query exhibitions table instead
   - Maps ex.event_video as video_url (for compatibility)
   - Returns both video_url AND event_video fields

Result: API now returns exhibition data with video field populated


File: event.php
──────────────────────────────────────────────────────────────────────────────

VIDEO FIELD CHECK (Line 436):
   Before: if (event.video_url) { displayVideo(event.video_url); }
   After:  const videoUrl = event.video_url || event.event_video;
           if (videoUrl) { displayVideo(videoUrl); }

Result: JavaScript now handles both field names from API


COMPLETE FLOW:
──────────────────────────────────────────────────────────────────────────────

1. Admin creates exhibition + adds video URL → saves to exhibitions.event_video
2. User visits spaces.php → sees past exhibitions
3. User clicks exhibition → redirects to event.php?title=slug
4. event.php calls api/get_event_details.php?title=slug
5. API searches exhibitions table → FINDS exhibition ✓
6. API returns exhibition data with video_url field ✓
7. event.php displays video ✓
