================================================================================
                    SLUG ARCHITECTURE ANALYSIS & PLAN
                Database-Driven, English-Only, Language-Aware
================================================================================

YOUR REQUIREMENT:
  ✓ Slug must be database-driven (not hardcoded or frontend-generated)
  ✓ Slug must be English-only (no Arabic slugs)
  ✓ Support ?lang=en and ?lang=ar to change content
  ✓ Slug stays same, only content changes with language parameter

================================================================================
CURRENT STATE (PROBLEMS)
================================================================================

BLOG SYSTEM:
  ❌ Slug generated on frontend: titleSlug = title.toLowerCase().replace(...)
  ❌ Uses title parameter: blogPageDetails.php?title=my-blog-post
  ❌ Database slug field exists but NOT used
  ❌ Inconsistent slug generation

EVENT SYSTEM:
  ❌ Database slug field exists but NOT used in URLs
  ❌ Uses ID parameter: event.php?id=123
  ❌ Frontend generates slug from title
  ❌ Inconsistent with database

PRESS SYSTEM:
  ❌ No slug support at all
  ❌ No detail page for individual press releases
  ❌ No URL structure for press items

================================================================================
PROPOSED SOLUTION
================================================================================

CORE PRINCIPLE:
  Slug is stored in DATABASE (English only)
  Language parameter (?lang=ar) changes CONTENT only, not slug

URL STRUCTURE:

  BEFORE (WRONG):
    blog.php?title=My%20Blog%20Post&lang=en
    event.php?id=123&lang=en
    press.php (no detail page)

  AFTER (CORRECT):
    blog.php?slug=my-blog-post&lang=en
    event.php?slug=dior&lang=en
    press.php?slug=press-release&lang=en

LANGUAGE BEHAVIOR:

  blog.php?slug=my-article&lang=en
    → Fetches blog with slug "my-article"
    → Returns English content (title_en, content_en)
    → Displays in English

  blog.php?slug=my-article&lang=ar
    → Fetches SAME blog with slug "my-article"
    → Returns Arabic content (title_ar, content_ar)
    → Displays in Arabic

  IMPORTANT: Slug NEVER changes, only content changes!

================================================================================
SLUG GENERATION RULES
================================================================================

ENGLISH SLUG GENERATION (Database):

  Input: "My Blog Post"
  Process:
    1. Lowercase: "my blog post"
    2. Replace spaces with hyphens: "my-blog-post"
    3. Remove special characters: "my-blog-post"
    4. Remove multiple hyphens: "my-blog-post"
    5. Trim hyphens: "my-blog-post"
  Output: "my-blog-post"

  Examples:
    "Dior" → "dior"
    "Anastasia Beverly Hills" → "anastasia-beverly-hills"
    "Press Release!" → "press-release"
    "YSL" → "ysl"

WHY ENGLISH-ONLY SLUGS?

  ✓ Consistency: Same slug regardless of language
  ✓ SEO: Search engines prefer English slugs
  ✓ Shareability: URL works in any language
  ✓ Simplicity: No encoding issues with Arabic
  ✓ Performance: Faster database lookups
  ✓ Reliability: No character encoding problems
